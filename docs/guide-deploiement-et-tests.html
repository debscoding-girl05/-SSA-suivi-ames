Guide de déploiement & de test

Application Suivi des Âmes — mettre l'application en ligne et vérifier que tout fonctionne, étape par étape.

Destiné à l'équipe technique chargée de la mise en ligne — aucune connaissance en programmation n'est nécessaire, seulement de suivre les étapes dans l'ordre.

Document de travail — août 2026 · Dépôt GitHub : debscoding-girl05/-SSA-suivi-ames (branche main)

1Avant de commencer

Comptez environ 45–60 minutes pour la première mise en ligne. Prévoir :

  • Une carte bancaire internationale (Visa/Mastercard) qui fonctionne depuis le Cameroun, ou une carte virtuelle (ex. Wise) rechargée à l'avance — Render, Supabase et Resend prélèvent automatiquement chaque mois.
  • Un accès au dépôt GitHub du projet (debscoding-girl05/-SSA-suivi-ames).
  • Une adresse email pour créer les comptes Render / Supabase / Resend.
  • Un ordinateur avec un terminal (pour lancer 1–2 commandes fournies plus bas — copier/coller uniquement).
Budget
Environ 32 $/mois (Render 7 $ + Supabase 25 $) + ~12 $/an de nom de domaine. Détail complet et alternative gratuite dans docs/DEPLOYMENT.md du dépôt.

2Créer la base de données (Supabase)

  1. Compte sur supabase.com → New project (choisir une région proche, ex. Europe).
  2. Dans Project Settings → Billing, passer le projet en plan Pro (25 $/mois).
  3. Dans Project Settings → Database → Connection string → URI, copier l'adresse. Elle ressemble à : 
    postgresql://postgres:[MOT_DE_PASSE]@db.[REF].supabase.co:5432/postgres
    → c'est la valeur de DATABASE_URL (à garder de côté pour l'étape 6).

3Créer l'espace de stockage des photos (Supabase Storage)

  1. Dans le même projet Supabase : Storage → New bucket.
  2. Nom exact : rapport-attachments.
  3. Public bucket : désactivé (OFF) — ces photos peuvent concerner des personnes suivies, elles ne doivent pas être publiques.
  4. Dans Project Settings → API, noter deux valeurs : Project URL (= SUPABASE_URL) et la clé service_role (= SUPABASE_SERVICE_KEY, pas la clé anon).

4Générer les clés de notifications push

Aucun compte à créer — une seule commande dans le terminal :

npx web-push generate-vapid-keys

Copier les deux valeurs affichées (VAPID_PUBLIC_KEY et VAPID_PRIVATE_KEY). Pour VAPID_SUBJECT, utiliser une adresse email de contact au format mailto:contact@exemple.com.

5Créer le compte email (Resend)

  1. Compte gratuit sur resend.com (gratuit jusqu'à 3 000 emails/mois).
  2. API Keys → Create API Key → copier la clé (= RESEND_API_KEY).
  3. Envoi possible tout de suite depuis l'adresse partagée par défaut. Si l'église a son propre nom de domaine, le vérifier dans Domains → Add Domain pour une meilleure délivrabilité (optionnel, peut se faire plus tard).

6Déployer sur Render

  1. Compte sur render.com, puis connecter le compte GitHub du projet.
  2. New + → Blueprint → sélectionner le dépôt -SSA-suivi-ames. Render détecte automatiquement le fichier render.yaml et propose de créer deux services : ssa-api (le serveur) et ssa-web (le site).
  3. Avant de valider, renseigner les champs demandés pour ssa-api :
VariableValeur
DATABASE_URLcopiée à l'étape 2
SUPABASE_URL / SUPABASE_SERVICE_KEYcopiées à l'étape 3
VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY / VAPID_SUBJECTgénérées à l'étape 4
RESEND_API_KEYcopiée à l'étape 5
CORS_ORIGIN / APP_URLlaisser vide pour l'instant → étape 7

Pour ssa-web, laisser VITE_API_URL vide pour l'instant.

7Relier les deux adresses

Render donne une adresse à chaque service (ex. https://ssa-api.onrender.com et https://ssa-web.onrender.com) — elles doivent se connaître mutuellement :

  1. Noter les deux adresses réelles affichées dans le tableau de bord Render.
  2. Sur ssa-web : régler VITE_API_URL = adresse de ssa-api, puis Manual Deploy.
  3. Sur ssa-api : régler CORS_ORIGIN et APP_URL = adresse de ssa-web (redéploiement automatique).

8Créer le premier compte (Pasteur)

Sur Render, ouvrir l'onglet Shell du service ssa-api, puis coller (en remplaçant l'email, le mot de passe et le nom) :

npm run create-pasteur -- pasteur@exemple.com "UnMotDePasseSolide!23" "Nom du Pasteur"
Important
Ne jamais utiliser npm run seed sur le vrai site : cette commande crée aussi des comptes de démonstration avec des mots de passe visibles publiquement. Utiliser uniquement create-pasteur.

Une fois connecté avec ce compte, inviter le reste de l'équipe depuis Dirigeants → Inviter un dirigeant — chacun reçoit un lien par email pour créer son propre compte.

9Checklist de test — à faire après chaque mise en ligne

À cocher un par un. Si une case ne passe pas, voir « En cas de problème » à la fin.

Accès de base

  • https://votre-api.onrender.com/health répond {"status":"ok","database":{"backend":"postgres"}}.
  • Le site s'ouvre, la connexion avec le compte Pasteur fonctionne, le tableau de bord affiche des données.

Départements et équipe

  • Créer un département de test dans Départements.
  • Inviter un dirigeant de test — l'email d'invitation arrive bien (pas seulement visible dans les logs Render).
  • Le lien d'invitation permet de créer un compte et de se connecter.

Annuaire et assignés

  • Ajouter un assigné (une âme suivie) à un dirigeant depuis sa fiche.
  • Dans le formulaire d'ajout, taper un nom déjà existant dans « Déjà dans l'annuaire ? » → il apparaît, et « Rattacher à moi » fonctionne sans avoir à ressaisir les informations.
  • La page Annuaire affiche le total de contacts et les boutons Précédent/Suivant si plus de 50 résultats.

Fiches hebdomadaires

  • Créer une nouvelle fiche (Choristes, Audiovisuel, Huissier ou Faiseur de Disciples) → les noms des assignés apparaissent déjà pré-remplis.
  • Ajouter une photo (« Photo de la fiche papier ») → elle s'affiche en miniature ; recharger la page → la photo est toujours là (preuve que le stockage Supabase fonctionne, pas juste le disque temporaire du serveur).
  • Télécharger le PDF de la fiche → le fichier s'ouvre correctement, avec les bonnes informations.

Relances et notifications

  • Sur le tableau de bord, la liste « À relancer » propose un bouton Appeler / WhatsApp à côté de chaque dirigeant en retard.
  • Dans Profil, activer « Notifications sur cet appareil » → la permission du navigateur est demandée et acceptée.
  • Depuis le Shell Render, lancer npm run digest:test → une notification apparaît sur l'appareil qui a activé le push, même onglet fermé.

Sécurité

  • Se connecter avec un compte encadreur et vérifier qu'il ne voit que ses propres assignés (pas ceux des autres).
  • Changer le mot de passe du compte Pasteur depuis Profil (indispensable si create-pasteur a été fait avec un mot de passe provisoire).

10En cas de problème

SymptômeÀ vérifier
Le site met 30–60 secondes à répondre au premier chargementNormal si le plan Render est resté sur « Free ». Vérifier que ssa-api est bien sur le plan Starter.
Les photos de fiches disparaissent après quelques joursSUPABASE_URL / SUPABASE_SERVICE_KEY mal renseignées → les photos sont alors stockées sur le disque temporaire de Render, qui s'efface.
Les emails n'arrivent jamaisVérifier RESEND_API_KEY sur Render, et regarder les logs du service ssa-api (onglet Logs) pour un message commençant par [email].
Les notifications push n'arrivent pasVérifier que les 3 variables VAPID_* sont bien renseignées et identiques à celles générées à l'étape 4 (elles ne doivent jamais changer une fois des personnes abonnées).
Erreur de connexion à la base de donnéesVérifier DATABASE_URL (mot de passe correctement recopié) et que DATABASE_SSL=true est bien réglé.
